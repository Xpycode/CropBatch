## Decisions
- **One screenshot per visual topic, none for reference topics** — primary guard against help-bundle bloat. Held the line at 6 (added the optional watermark shot on request; refused a 3rd effects image).
- **JPEG over PNG** for help screenshots — content is photographic; q0.82 gives ~4–6× smaller with no meaningful quality loss at help-pane size.
- **Cap width at 900px** — exact Retina @2x for the help detail pane; wider is wasted bytes.
- **Reuse README screenshots as sources** rather than recapturing from the running app — faster, and they already cover 5 of 6 features.
- Named images by topic id (`getting-started.jpg`, etc.) to match `.md` basenames.

## Blockers / Risks
- **MarkdownUI local-image resolution (UNVERIFIED):** `MarkdownUI` does not resolve relative local image paths (`![](snap.jpg)`) by default — needs an `imageProvider` mapping filename → bundled resource, or absolute `file://` URLs. The `HelpMenu` renderer is owned by the appHELP agent; if no bundled-image provider is wired, the help window will show broken-image placeholders. **Must confirm with appHELP side before shipping.**
- New `.jpg` images must end up in the CropBatch target's bundled resources — the synchronized `Help/` group should include them automatically (Xcode 16 file-system groups), but verify they appear in the built `.app`.
