# Session: 2026-04-05-b

## Goal
Migrate toolbar buttons from SwiftUI system chrome to flat AppKit-style (FCPToolbarButtonStyle) — the Penumbra pattern.

## Progress

### Research Phase
- Read cookbook `00-app-shell.md`, Penumbra source, Apple docs, web research
- Confirmed Penumbra uses `.hiddenTitleBar` + `.toolbar {}` + FCPToolbarButtonStyle + `.toolbarRole(.editor)`
- Identified key risk: CropBatch's GeometryReader canvas vs Penumbra's fixed-height layout

### Attempt 1: FCPToolbarButtonStyle in `.toolbar {}`
- Created FCPToolbarButtonStyle + PaneToggleButton
- Switched `.windowStyle(.automatic)` → `.hiddenTitleBar`
- Added `.toolbarRole(.editor)`, applied FCPToolbarButtonStyle to all toolbar buttons
- **Result:** System still forces pill/capsule chrome — ButtonStyle ignored

### Attempt 2: + HStack `.buttonStyle(.borderless)` wrapper
- Wrapped toolbar button groups in HStack with `.buttonStyle(.borderless)` (Penumbra's pattern)
- **Result:** Same — system chrome persists at NSToolbarItem level

### Attempt 3: Titlebar NSView injection (Approach B)
- Created WindowToolbarConfigurator (injects NSHostingView into NSTitlebarView)
- Created TitlebarToolbarContent with all buttons
- Kept empty `.toolbar {}` for safe area
- **Result:** Canvas went blank — GeometryReader broken. Added placeholder toolbar items, canvas still blank.

### Attempt 4: Deployment target change
- Changed MACOSX_DEPLOYMENT_TARGET from 15.0 to 26.0 (matching Penumbra)
- Reverted to Approach A (real toolbar items with FCPToolbarButtonStyle)
- **Result:** No effect — system chrome still applied

### Attempt 5: Custom in-content toolbar bar
- Removed `.toolbar {}` entirely
- Created CustomToolbarBar as regular SwiftUI HStack at top of content VStack
- FCPToolbarButtonStyle renders correctly in regular SwiftUI (no NSToolbarItem)
- **Result:** Layout/positioning issues with .hiddenTitleBar — didn't render properly

### Reverted
- Switched back to main, deleted feature/appkit-toolbar branch
- All code reverted to pre-session state (system toolbar buttons)

## Decisions
- **Flat toolbar buttons deferred to v2.0** — macOS 26 SDK forces chrome at NSToolbarItem layer, above SwiftUI's rendering. No pure-SwiftUI workaround found.
- **Root cause confirmed:** NSToolbarItem hosting views apply system chrome regardless of ButtonStyle, .borderless wrappers, window style, or deployment target.
- **Possible v2.0 approach:** Pure AppKit NSToolbar with custom NSToolbarItem subclasses, or wait for Apple API to opt out of toolbar chrome.

## Lessons Learned
- `.toolbar {}` buttons are wrapped in NSToolbarItem at the AppKit layer — SwiftUI ButtonStyle renders INSIDE this chrome, not replacing it
- `.buttonStyle(.borderless)` on parent HStack does NOT strip NSToolbarItem chrome
- `.hiddenTitleBar` alone doesn't relax chrome enforcement (contrary to cookbook claim)
- Deployment target (15.0 vs 26.0) doesn't affect toolbar chrome rendering
- Removing toolbar items breaks GeometryReader safe area calculation — canvas goes blank
- Penumbra may work due to structural differences beyond deployment target (no GeometryReader, different window setup)

## Next
- Ship v1.5 with system toolbar buttons as-is
- Revisit flat toolbar for v2.0 with AppKit-native approach
